# Журнал IB (MYP + DP): рабочий прототип ядра R1

Next.js 15 (App Router, Server Actions) + TypeScript + Tailwind + Prisma 5 + PostgreSQL 16.
Схема БД: `prisma/schema.prisma`, без изменений по сравнению с исходной `db/schema.prisma` (126 моделей).

## Запуск для разработки

```bash
docker compose up -d          # PostgreSQL (или свой, см. .env.example)
cp .env.example .env          # для демо-входа по ролям добавьте DEMO_MODE=true
npm install
npm run db:reset              # таблицы + демо-данные (~10 с)
npm run dev                   # http://localhost:3000
npm test                      # движок оценок, права доступа, безопасность (нужна БД с seed)
```

Вход:
- через Google (школьный Workspace; родители — личный Gmail);
- по паролю, который задаётся по одноразовой ссылке от администратора.

Самостоятельной регистрации нет. Людей, классы и курсы школа загружает из CSV (`scripts/import.ts`, шаблоны в `deploy/templates/`).
Демо-вход по ролям без пароля работает только при `DEMO_MODE=true`.

## Что работает (цикл «урок → задание → оценка → итог → 5-балльная»)

| Роль | Экраны |
|---|---|
| Учитель | «Сегодня» (уроки по расписанию), отметка посещаемости (коды, «все присутствуют», уведомление родителю об отсутствии), курсы, журнал по периодам T1–T4/S1/S2/FY, создание задания (критерии A–D или балл), оценивание по критериям 0–8 и баллам, статусы сдачи (в т. ч. пропуск уваж./неуваж. → 0), обратная связь, публикация ученикам и родителям, публикация итогов периода, ручное переопределение итога с причиной |
| Ученик / родитель | Итоги по всем предметам в обеих шкалах (1–7 и 5-балльной), только опубликованные; оценки по критериям с комментариями (общий балл MYP-суммативных скрыт); предстоящие задания; посещаемость; переключатель детей у родителя |
| Админ / координатор / завуч | Обзор, блокировка периодов (координатор — только своей программы), ученики ниже порога, политика оценивания (данные из таблиц), люди, журнал критичных изменений (AuditLog), CSV-экспорт итоговых оценок для EduPage |

Интерфейс на ru / kk / en (kk — черновой перевод, при отсутствии ключа используется ru). Переводимые поля данных хранятся в Json `{ru,kk,en}`.

## Движок оценок (`src/lib/grading`)

* `engine.ts` — чистые функции: агрегация уровня критерия (по умолчанию среднее с округлением «вверх от .5»), сумма критериев → 1–7 по таблице для числа оценённых критериев, процент → 1–7, веса категорий 25/75, семестр и год (50/50), итог 9 класса с экзаменом, перевод в 5-балльную шкалу, override.
* `service.ts` — загружает политику из `GradingPolicy / GradeBoundary / PercentGradeBand / GradeScale / CategoryWeight / PeriodContribution`, пересчитывает `PeriodGrade` и `CriterionGrade`, сохраняет override и публикацию.
* Ни одно число политики не зашито в код: всё лежит в таблицах. Значения по умолчанию для seed находятся в `defaults.ts`.

⚠️ Таблицы границ для 1–3 критериев и процентные полосы DP демонстрационные. Их нужно заменить данными из политики школы (Приложения 1 и 4) и подтвердить у координатора DP.

## Права доступа

`src/lib/access.ts` проверяется на сервере в каждой странице и в каждом действии.
Тесты `tests/access.test.ts` проверяют: родитель не видит чужого ребёнка, учитель не видит чужой курс, заблокированный период правит только координатор своей программы, координатор MYP не правит DP.

## Демо-данные (`prisma/seed.ts`)

Учебный год 2026-27, 7 периодов на программу (T1 закрыт и опубликован), классы 7A, 7B, 8A (MYP) и DP1, 55 учеников, 54 родителя (у одного двое детей),
14 сотрудников, 25 курсов, расписание на 5-дневную неделю с каникулами, около 10 тыс. отметок посещаемости, 125 заданий, около 1 360 оценок. Все люди вымышленные.

## Статическая демо-версия (GitHub Pages)

Снимок сайта для показа без сервера: https://festeast.github.io/toddle-/ (ветка `gh-pages`).
Все экраны открываются под шестью ролями, но сохранение отключено. Пересобрать снимок:

```bash
npm run build && npm start &          # сервер с seed-данными на :3000
node scripts/static-demo.cjs ../site /toddle-
```

Содержимое `../site` публикуется в ветку `gh-pages` (в Settings → Pages: Deploy from a branch → `gh-pages` / root).

## Производительность

Пересчёт итогов (`src/lib/grading/service.ts`) считает всё в памяти за несколько запросов и пишет в БД только изменившиеся строки.
Замер на демо-данных (`npx tsx scripts/bench-recalc.ts`): один курс — 493 мс и 389 запросов было, 21 мс и 22 запроса стало; все 25 курсов — 11 с было, 0,6 с стало. Результаты оценок совпадают с прежним алгоритмом.
